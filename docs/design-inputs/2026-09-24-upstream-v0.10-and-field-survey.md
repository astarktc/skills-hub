## Verdicts in one paragraph each

**Features.** Upstream grew sideways — tags, bulk ops, Management Center, scheduled refresh, a v0.8 sidebar redesign, and in v0.10 a
~9,400-line git-backed multi-device sync plus a recycle bin — but still has no project entity (per-target `scope='project'` +
`project_path`, a recent-projects list). Nothing is cherry-pickable; every port below is "build the verb in this fork's shape".

**Code.** Toolchain improved (clippy `-D warnings` clean, 394/394 `cargo test`, a build-failing network-boundary lint) but the
architecture stagnated under the pile: string error codes 7 → 20 parsed at 35 frontend sites (JSON inside a string, a match on Chinese
prose), `commands/mod.rs` 985 → 3,213 with 51 non-command functions, `App.tsx` 2,086 → 4,243 with zero hooks, install last mile
copy-pasted ×3, 2 refactor commits in 377, device sync as one 16,001-line commit. Three modules are deeper than ours (§C).

**Field.** ~20 desktop managers now exist (5 in April); none combines library + GUI + project matrix + onboarding takeover + edit
overlay surviving refresh + content identity + unlocatable repair. Closest peers `xingkongliang/skills-manager` (4.9k★) and
`what1f/kitter` (302★). The fork decision holds; what changed is that several things we planned to build now have borrowable designs.
