# Replace the string-prefix error contract with a tagged enum

Status: resolved

Type: grilling
Blocked by: 01

## Question

The Rust→TS error interface is "a string that may start with one of N pipe prefixes" — shipped 8 prefixes vs 5 documented in AGENTS.md, parsed in 3 dialects (`format_anyhow_error` whitelist at commands/mod.rs:40–113; App.tsx prefix parsing + raw-prose substring sniffing incl. Chinese literals at 200–232; `formatProjectError` in useProjectState.ts:62–78; plus `.contains("CANCELLED|")`-style ad-hoc prefixes inside installer.rs:1670–1695).

Decide, then implement (per map Notes):

- The serde-tagged error payload shape (Tauri supports structured `Err`), e.g. `{ code: "TOOL_NOT_WRITABLE", tool, path }` — full variant list (superset of the 8 shipped prefixes + CANCELLED/RATE_LIMITED?).
- Where user-facing prose lives: today `format_anyhow_error` composes Chinese hint copy backend-side — move all message composition to a single frontend `describeCommandError(e, t)` module using i18n keys (EN & ZH)?
- Migration strategy: flip all commands at once, or keep the prefix strings as a compatibility `Display` while call sites migrate?
- Coordinate with ticket 07 (TS type generation): if the generation tool from ticket 06's research is adopted first, the enum's TS mirror is generated, not hand-written.
- Update AGENTS.md's five-prefix contract section to describe the new contract.

Context: scan finding 3; report card #3. ADR note: this deliberately replaces a documented invariant — the drift (8 ≠ 5) is the argument.

## Answer

Landed green in `ac3395c`. All decisions grilled in one round; Alex accepted all recommendations.

**Pre-grill findings that shaped the decisions**: 10 prefix codes existed in the wild, not 8 —
`CANCELLED|`/`RATE_LIMITED|` were matched with `.contains()` *inside* installer.rs/github_download.rs
as in-band control-flow signals (a third dialect). `MULTI_SKILLS|`/`SKILL_INVALID|` were parsed
nowhere frontend-side (the candidate-picker flow replaced them; they leaked raw). The GitHub-clone
hint copy was Chinese-only for all locales. An 11th ad-hoc prefix `UNSAFE_PATH|` existed unparsed
(now plain prose).

**Decisions (Q1–Q8, all as recommended)**:

1. **Wire shape**: internally tagged — `#[serde(tag = "code", rename_all = "SCREAMING_SNAKE_CASE",
   rename_all_fields = "camelCase")]` → `{ code: "TOOL_NOT_WRITABLE", tool, path }`; TS narrows on
   `code` natively; codes stay grep-able against old logs.
2. **Variants (12)**: `ToolNotInstalled{tool}`, `TargetExists{path}`, `ToolNotWritable{tool,path}`,
   `SkillInvalid{reason}`, `MultiSkills`, `DuplicateProject{path}`, `AssignmentExists{project,skill,tool}`,
   `NotFound{kind,id}`, `Cancelled`, `RateLimited{resetMinutes}`, `GitCloneFailed{kind,detail}`,
   `Other{message}` (safety valve — prose reaching users through it = a typed variant is due).
3. **Prose placement**: backend classifies (it has the error chain: `GitCloneFailureKind` =
   tls/auth/notFound/dns/timeout/refused/unknown), frontend owns ALL copy via one
   `describeCommandError(err, t): string | null` module (`src/commandError.ts`; `null` = silent
   cancellation). Fixes EN users receiving Chinese hints. The two prose sniffs (central-repo
   duplicate, Chinese no-skills literal) moved into its `Other` branch as residue.
4. **Migration**: flipped all 59 commands at once through the single `.map_err` choke point; no
   compatibility `Display`; `format_anyhow_error` + `format_global_sync_error` deleted.
5. **Core signaling**: new `core/errors.rs` `SignalError` (7 conditions) raised via
   `bail!(SignalError::…)` through anyhow chains; recovered by **downcast** at the command seam
   (`CommandError::from_anyhow`, by-value downcast for `SignalError` then `GlobalSyncError`) and at
   installer's internal retry/fallback match — zero string sniffing remains (verified by sweep).
   Ticket 01's `GlobalSyncError` unchanged; mapped via `From<GlobalSyncError> for CommandError`.
6. **Seam placement**: wire enum in `commands/error.rs` (wire = commands' job), signals in
   `core/errors.rs` (domain conditions = core's job).
7. **ts-rs adopted now, types-only, for this enum** (tool decision was already locked by research
   ticket 06): `ts-rs = "12"` dep, `src-tauri/.cargo/config.toml` env (`TS_RS_EXPORT_DIR=../src/bindings`,
   `TS_RS_LARGE_INT=number`), bindings generated by `cargo test`, committed, CI diff-guard added
   (`git diff --exit-code -- ../src/bindings` after `cargo test --all`). **Ticket 07 inherits a
   working pipeline** and only annotates the 23 DTOs + swaps the mirror files. Note: `rust-version`
   bumped 1.77.2 → 1.88 (ts-rs 12 MSRV; toolchain is 1.97, CI uses stable).
8. **Docs**: AGENTS.md five-prefix section replaced with the new contract; first ADR created
   (`docs/adr/0001-tagged-command-error-contract.md`).

**Frontend collapse**: `formatErrorMessage` (App.tsx), `formatProjectError` (useProjectState) and all
~15 prefix-parse sites deleted; ~52 `err instanceof Error ? err.message : String(err)` sites now go
through `describeCommandError`/`errorCode`/`toCommandError`; discriminating sites (skip-tool,
collect-errors, target-exists detail) switch on `e.code` with typed payload access. `showActionErrors`
filters empty messages (centralized cancellation silencing). New i18n keys EN+ZH: `skillInvalid`,
`skillInvalidMissingSkillMd`, `multiSkillsRepo`, `rateLimited(NoEta)`, `gitClone{Tls,Auth,NotFound,Dns,Timeout,Refused,Unknown}`.

**Tests**: commands tests now assert downcast recovery + exact serialized wire shapes;
github_download/installer/project_ops tests assert on `SignalError` variants, not strings.
Gate: `npm run version:check` + `npm run check` green; `cargo test --all` 197 passed.

**Unblocks**: ticket 03 (batch sync) — its per-tool error collection can now match on
`CommandError`/`SignalError` variants instead of strings.
