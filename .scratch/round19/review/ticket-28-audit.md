## Defects found and fixed

1. **Trees ref URL encoding (functional).** The branch was interpolated verbatim into a path parameter. A shebang fallback is not an adequate substitute for a known encoding fix: non-shebang executables would remain non-executable. Fixed with the existing `urlencoding` dependency; no extra requests and no trait change. Red proof: `slash-ref-red.log` (expected execute bits 73 decimal / `0111`, observed 0). Green proof: `fixes-green.log`, `rust-final.log`.
2. **Umask-dependent assertions (test portability).** Reproduced with `(umask 077; cd src-tauri && cargo test the_trees_answer_restores_executable_bits_on_every_written_file)`: exit 101, actual 457 decimal / `0711`, expected 493 / `0755`. Changed assertions for default-created files to the execute-bit contract; kept full permission assertions where fixtures set permissions explicitly. No process-global umask mutation inside parallel tests. `umask-final.log` passes all HTTP adapter tests plus Refresh and copy pins under 077. The ordinary Ubuntu/macOS umask of 022 explains the old green gate, but is not a reliable test precondition.
3. **Unix-only test helper cfgs (warning hygiene).** `listing_dir`, `tree_entry`, `serve_skill`, `tree_body`, and `download_skill` had no non-Unix callers but were compiled there. Added matching Unix cfgs. Production Windows behavior was already correct. This finding is static, not a claimed Windows compiler reproduction.

Also strengthened coverage for 404, malformed JSON, absent tree entries, and cancellation at the exact pre-Trees boundary. Documentation-only clarifications match existing exemptions rather than changing policy.

## GitHub REST research: slash branches and SHA alternative

Sources fetched on 2026-10-27 (only this checklist question used external research):

- [Get a tree](https://docs.github.com/en/rest/git/trees#get-a-tree): “Returns a single tree using the SHA1 value or ref name for that tree.” `tree_sha`: “The SHA1 value or ref (branch or tag) name of the tree.” The same page documents truncation and the recursive tree limit (100,000 entries / 7 MB).
- [Troubleshooting the REST API — 404](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#404-not-found-for-an-existing-resource): “any path parameters must be URL encoded. For example, any slashes in the parameter value must be replaced with `%2F`.” It says unencoded slashes cause the endpoint URL to be misinterpreted.

The Trees endpoint page itself does **not** add a branch-specific slash exception. The documented encoding requirement, rather than a live API probe, is the basis for the fix. I did not test whether GitHub currently tolerates the unencoded multi-segment form on this particular route, and do not claim an observed live 404. The local regression server enforces the documented URL and demonstrates that the old code silently loses a non-shebang executable's bit when that route is not accepted.

`git_acquisition::fast_path` already holds `revision = api.branch_sha(coords)` immediately before `api.download_directory(coords, ...)`. It could cheaply pass a cloned `GithubCoords` with `branch = revision` without changing the trait signature, pinning both Contents and Trees to the same immutable revision while retaining the original branch in `Acquired`. Passing a separate mode-only SHA would require broadening the seam and would not pin file bytes. I chose the smaller, safe path-encoding fix here: changing the semantic contract of the coordinates sent to every adapter/stub is unnecessary for this ticket. Existing branch-movement races remain outside scope; using the same symbolic ref satisfies the accepted specification.
