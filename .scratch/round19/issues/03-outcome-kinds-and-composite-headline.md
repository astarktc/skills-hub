# 03 — Outcome kinds `declined` and `cancelled`; composite count headline in the fold

Status: done — 27c936f
Blocked by: 01
Spec: `.scratch/round19/spec.md` — D10 (grill Q8). Source: `archive/round18/review/flows.md` § "The fold's precedence contract".

## Why

`conflict › failure › skipped › success` picked "Refresh complete — invocation Edit conflicts need review" over five
failures; a cancelled Refresh reads "0 skills refreshed, 15 failed"; "Keep existing" is a red toast; Edit-with-drift
never says "saved".

## Work

### Backend

- `core/refresh.rs`: a cancelled run answers rows of a new kind **`Cancelled`** (its own variant in the per-skill
  outcome enum, beside `Refreshed`/`Failed`/`Skipped`), not `Failed { Cancelled }`. The same variant for candidates
  the new install batch (ticket 04) never reached — define the variant here so 04 reuses it. `specta::Type`, bindings
  regenerated.
- `global_sync`'s per-target outcome gains **`Declined`** (the pair the operator kept — ticket 02 records it as
  `disabled`; the report row says *declined*, not failed and not skipped).

### Frontend (`src/lib/reportOutcome.ts` + tests + i18n; nothing else)

- `Outcome` gains a **composite headline**: counts per kind in a fixed order — done · failed · skipped · declined ·
  cancelled · to review — rendered as "12 refreshed · 5 failed · 4 skipped · 1 Edit to review" (i18n with plural
  keys; a zero count is omitted; the verb is the action's: refreshed / installed / synced / imported / removed /
  assigned). The toast `tone` keeps a precedence, now **failure › conflict › skipped › declined › success**;
  `cancelled` alone is neutral ("Refresh cancelled — nothing was changed").
- `declined` rows produce **no error entry**; they produce one quiet warning-free line in the report
  ("ts-reset: kept your existing Claude Code folder").
- Edit with target drift: headline "Saved · 2 targets failed" (success tone is wrong; use warning) — the Edit *did*
  save centrally (ADR-0004).
- `refreshSummary` no longer drops the skipped count when anything failed.
- `completion` semantics unchanged (reload / closeModal / conflict); the `conflict` completion still fires when any
  conflict exists, independent of the headline.
- Every existing test in `reportOutcome.test.ts` is re-read against the new contract; add cases: mixed Refresh (the
  observed 5/6/4/1), cancelled Refresh, declined-only sync, Edit saved-with-drift, install batch with cancelled tail.
- `useNotificationHistory` stores the headline + the entries (grouping by run is ticket 14; keep the shape ready — a
  `runId` per fold call is cheap to add now).

### Fixture

- Cancelled Refresh answers the all-`Cancelled` report instead of throwing `CANCELLED` (a listed fixture gap).

### Headline grammar (`compositeHeadline(t, verb, counts, review?)`)

Parts in fixed order, zero counts omitted, joined by `HEADLINE_SEPARATOR` (" · "); all zero → the done part at 0:
done (`outcome.done.<verb>`, verbs refreshed/installed/synced/imported/removed/assigned/enabled/disabled) · failed ·
targets failed (Sync targets under a unit that succeeded) · skipped · declined ("kept existing") · cancelled · to review
(`edits` "Edit(s) to review" or `originals` "original(s) to review"). All `_one`/`_other` plural keys.

- Refresh (batch): "12 refreshed · 5 failed · 6 targets failed · 4 skipped · 1 Edit to review"; empty → "0 refreshed".
- Cancelled Refresh (nothing applied, nothing failed): "Refresh cancelled — nothing was changed" (neutral); batch of
  one: "alpha: update cancelled — nothing was changed".
- Bulk sync: "1 synced · 1 failed · 2 skipped"; declined-only: "2 kept existing" + notes as detail.
- Import: "3 imported · 1 failed · 2 targets failed · 1 skipped · 1 kept existing · 2 originals to review" (+ forced
  lines and notes as detail).
- Install (picker): "2 installed · 3 cancelled"; single git/local clean keeps "Git skill created." / "Local skill
  created."; with drift "1 installed · 1 target failed".
- Edit with drift: "Invocation setting saved · 2 targets failed" (warning).
- Declined note: "ts-reset: kept your existing Claude Code folder" (never an error entry; `Outcome.notes`, and the
  toast's `detail`; a declined toggle's toast *is* the note).
- Not converted (already count-bearing sentences, kept with a `tone`): project sync/removal folds (ticket 01's
  `disabledSkips.*` copy), removal "all"/toggle/bulkUnassign, delete, enable, toggle-on. The builder exposes every verb
  so 13/17 can move them onto it with their surfaces.

### Tone table (`headlineTone` → `toast.kind`)

| tone | when | kind |
|---|---|---|
| failure | failed > 0 or targets failed > 0 | warning |
| conflict | to review > 0 | warning |
| skipped | skipped > 0 | warning |
| declined | declined > 0 | info |
| neutral | only cancelled (with or without done) | info |
| success | otherwise | success |

`Outcome.toast` = `{ kind, tone, message, detail? }`; `Outcome.notes: string[]` new. `completion` unchanged; the
conflict completion fires whenever a conflict exists (the mixed Refresh test asserts it under a failure tone). Single
Update with a conflict keeps its sentence, toned by precedence. `refreshSummary`'s dropped-skipped bug is gone with it.
