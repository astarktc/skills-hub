# 01: Git Re-point — repair a Managed git skill whose upstream moved

**What to build:** A `git` Managed skill gets a **Re-point** action on its card (next to Update; the detail view too if it lists actions). It opens a Modal with one URL field. The operator pastes the skill's new GitHub URL (`https://github.com/<owner>/<repo>/tree/<branch>/<path>` or a repo URL); the app acquires from it exactly as an Update would; **only on success** it rewrites the record's `source_ref` + `source_subpath` and finalizes + Propagates to every target through the normal single-Update path, and the card shows the new source. On any failure (bad URL, 404, multi-skill ambiguity, network) the record is untouched and the error is the ordinary typed one. The `errors.githubSkillNotFound` copy (EN + ZH) gains one sentence pointing at Re-point. The glossary's **Unlocatable skill** / Re-point wording is widened: Re-point is one repair over two provenances (local: pick a folder; git: paste a URL).

**Blocked by:** None (can start immediately)

## Orchestrator notes

- Existing local Re-point: `core/unlocatable.rs::repoint_local_source` (store half) + command `repoint_local_skill_source` in `commands/mod.rs:~893` (re-point, then the `Ids([id])` Refresh entry point — two entry points in sequence, never nested inside the mutation guard). The local one writes first then Updates; **git Re-point must acquire first**. Preferred shape: the Refresh acquire phase takes an optional source override (a parsed `GitSource` + intent) for one id; finalize persists the new source fields together with the revision. Do not add a second acquisition pipeline — `git_acquisition::acquire` is the only way git bytes land.
- URL parsing: `git_acquisition::parse_github_url` (already returns clone_url/branch/subpath/api coords). A URL without a subpath on a multi-skill repo should resolve by the skill's name via `SkillIntent::NamedSkill(Some(name))`; a URL with a subpath uses `Subpath`.
- Refusal for non-git: follow `unlocatable::require_local`'s pattern but this one is operator-reachable only if the UI misbehaves — prose is acceptable per the round-5 rule, or reuse an existing typed variant if one fits.
- Frontend: `src/hooks/useSkillLibrary.ts` `handleRepointSkill` (~line 555) is the local flow; add `handleRepointGitSkill` sharing `runSingleRefresh`/`settleSingleReport`. `SkillCard.tsx` currently offers Re-point only inside the unlocatable badge row — add the git action beside Update for healthy git skills.
