# 01: Toast lifetime, reporter `notify()`, "Open log folder"

Status: done — b991fe7

**What to build:** An error toast stays on screen until the operator closes it; warnings linger ~5 s; successes ~2 s. The status reporter (`useStatusReporter`) becomes the only place that shows a toast or knows a duration: it gains one entry point, `notify(kind, title, message?)` with kind `error | warning | success | info`, and its existing setters (`setError`, `setSuccessToastMessage`, `showActionErrors`) and `runAction`'s success/failure paths route through it with unchanged signatures. The app-level `<Toaster>` carries no per-kind duration. Settings gains an "Open log folder" action backed by a new Tauri command that resolves the app log directory (where `tauri-plugin-log` writes) and opens it with the opener plugin the app already ships. Migrating the direct `toast.*` calls outside the reporter is ticket 02, not this one.

Source: `../spec.md` Q4 (entry point only), Q5; `../source-14-toast-lifetime.md` steps 1 and 3. Skill: **tdd** (reporter hook tests exist — extend them).
