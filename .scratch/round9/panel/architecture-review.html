Two live defects surfaced, both verified at HEAD: (1) release builds record content_hash = None at finalize → every copy‑mode project assignment reports Stale after every Update (tests are debug‑only, so blind); (2) finalize_update discards the old central bytes before replay_unlocked runs → a failed Edit replay is a failed Update with bytes already replaced. Both belong to candidates below; neither needs the deepening to be patched first.

Problem. "What is this skill's hash" is decided at five sites with three rules; the release/debug fork inside one of them makes copy‑mode assignments go Stale after every Update in shipped builds only (Windows without symlink privilege is exactly copy mode). Fable notes the round‑3 closure‑supplier decision fixed the rule and left the supply divergent.

Solution. One module owns computing, storing and answering a Managed skill's content hash; finalize and Edit replay write through it, Propagation / reconcile / same‑content read from it. The perf gate becomes that module's decision (or dies — it predates hashed reconcile).

  • locality: "hash absent" reasoned about once, not five times
  • leverage: Propagation and reconcile stop threading Option<&str>
  • test: finalize → propagate → reconcile through one interface with the real supplier
  • test: release policy becomes a value a test can pick
  • deletion test: already effectively deleted — complexity has reappeared at five sites

Problem. The tail is composed by hand in finalize_and_propagate_unlocked: finalize's atomicity ends before replay (verified), AcquiredUpdate carries a whole record snapshot that nothing re‑admits against the current row after the pool finishes (Delete/Re‑point during acquisition), git Re‑point is atomic while local Re‑point writes source_ref first (verified), and set_invocation_override is a third copy of the tail that logs propagation failures instead of returning report data — the one breach of the fan‑out rule.

Solution. One Update module whose interface is "bring this Managed skill's central copy to these bytes and settle its targets": admission of the acquired result, finalize + Edit replay + row settlement before recovery material is released, then Propagation. Git, local Re‑point, override and the Edit write are adapters choosing what the bytes are. installer.rs goes back to being the Add flows.

  • locality: one atomicity rule, one report shape for every central‑bytes change
  • leverage: Edit V2 adds an adapter, not a fourth tail
  • test: injected edit‑row failure → bytes, base, row and retry checked through one interface
  • test: tests/refresh.rs (1704 l) + tests/installer.rs (1418 l) stop splitting one pipeline by file
  • depends on #1 (the tail's hash step must be honest to test it)

Speculative O6

src/App.tsx:57-85, 150-170 · useSkillLibrary.ts:78-98, 339-345, 565-600 · useSyncOrchestration.ts

Problem. "Which surface over which id" is split across App, the library hook and sync orchestration; four fixes in 40 commits landed at the split (6bd05b7 3190623 cf47020 7b760ec). effectiveView (v1.2.8) removed the sharpest edge, so this is a shape complaint. Only alongside #4/#6.

Seams that earn their keep (all three seats agree)

  • mutation_guard — as deep as a lock gets; the entry‑point/unlocked‑seam discipline is the point.
  • git_acquisition::acquire(request, api) + the GithubApi trait and AcquireFn — two real adapters each; #3 deepens the callers, not it.
  • git_cache::fetch_through_cache per‑key coordination.
  • artifact_removal — scopes in, report out, one presence rule; ADR‑0002 stands. Keep it distinct from Propagation.
  • tool_adapters registry — wide by nature; narrowing it reintroduces name special‑casing.
  • SkillStore — 41 methods, but deleting it scatters SQL across a dozen modules.
  • invokeTauri + generated bindings + describeCommandError (ADR‑0001) — one deep interface end to end.

Top recommendation

#1 Content identity has one supplier, then #2 Update is one module.

#1 is small, two seats found it independently, and it is a verified shipped‑build defect the suite cannot see. #2 is where the second verified defect lives (replay after recovery is discarded) and where Fable, Astra and half of Opus converge; #1 is its prerequisite because the tail's hash step must be honest before the tail can be tested through one interface. #4 is the frontend lane that runs in parallel without touching a shared file. #3 is the next backend round: the ladder where the last three rounds spent their fix budget.

Patch‑now option: both defects can be fixed in v1.2.9 without the deepening — drop the debug/env gate (or read the row) at finalize; and either replay Edits before the backup is released or make a replay failure non‑fatal‑with‑conflict — then deepen in round 10 with a green baseline.
