# Accessibility audit — incumbent Skills Hub

2026-09-27 · Round 18, ticket 06 · **D5 is not met today.** This is a scoped implementation audit, not a conformance certificate or a design critique.

## Method and limits

- Fresh inspection of the running fixture at `http://localhost:5175`, scenarios `rich`, `first-run` and `failures`, latency 0 and 3; dark and light through Settings. No Tauri startup, real library access or source changes. Read D5/D6, the bake-off exclusions, PRODUCT, CONTEXT, ADR-0006 and the requested audit/checklist files. No findings were imported from the two critiques.
- T3 preview reported CSS viewports **1280×800** and **960×640**. Saved images below are 960×640 CSS views; image pixel dimensions can differ because of capture scaling. Repaint was forced before captures. Evidence is local, gitignored, under `/Users/alexstark/Projects/skills-hub/.scratch/round18/evidence/audit/`.
- Keyboard evidence uses **trusted `preview_press` events**, recorded at `keyup` with `document.activeElement`. Programmatic `.focus()` positioned the starting control for individual tests; helper clicks/text insertion established scenarios. **These are not six uninterrupted, keyboard-only end-to-end runs.** Where completion or traversal was not proved, the result is Partial, not Pass. Synthetic KeyboardEvents were not treated as proof of native Tab navigation.
- A hidden tab reports `document.hasFocus() === false` between calls: querying `:focus-visible` then produces false negatives. Focus measurements below were taken synchronously **inside trusted key events**, where `:focus-visible === true`. Initial transition samples are explicitly distinguished from settled focus styles. Native `outline:auto` rendering still needs verification in the shipping WebViews.
- Contrast uses WCAG 2.x sRGB relative luminance, `(Llighter + .05)/(Ldarker + .05)`, from computed foreground/background colours with ancestor background compositing. Oklab/alpha placeholders were resolved through an in-page canvas before calculation. Ratios are rounded to two decimals. Normal text needs 4.5:1; required non-text distinctions 3:1. Disabled controls are exempt from these contrast criteria. Tiny targets are not automatically AA failures: WCAG 2.2's 24px spacing exceptions must be assessed, not confused with a universal 44px requirement.
- No screen reader, forced colours, native file chooser, physical touch, Windows WebView2 or macOS WKWebView was exercised. `matchMedia('(prefers-reduced-motion: reduce)').matches` was **false**; preview exposes no reduced-motion emulation setting. Reduced-motion findings combine observed running animations with the loaded CSS and source, **not a claimed true-preference runtime test**.
- Late preview evaluations timed out/failed during failures-scenario Projects and after the zoom capture. Those are **test limitations, not attributed app bugs**. Fresh tabs recovered enough to check global tool configuration and toast colours; failures-matrix error/missing/pending states and a 200% screenshot remain unverified. Remove-project, Re-point and Edit have fresh DOM evidence but no saved screenshot; Explore detail was not exercised. Screenshot coverage is consequently incomplete, not “every surface captured”.
- Probe: `/Users/alexstark/Projects/skills-hub/.scratch/round18/evidence/audit/probe.js`. Fresh guideline fetch: `web-guidelines.md` in that directory. Impeccable detector output: `detector.json`; its gradient-logo/selected-project-border warnings are aesthetic, not accessibility violations, and were not promoted to failures here. Scope is D5, not an invented five-dimension product score.

## D5 gate verdict

1. **Keyboard-only completion of core flows — FAIL.** Add's Tool selection is removed from the focus order; Project selection has no keyboard entry point. Other sampled mutations activate with native keys, but dialog focus escapes, returns to BODY, and can disappear while the parent remains open. **Round 19 fix:** focusable named Checkbox/Switch primitives; a correct Project-selection pattern; keyboard-accessible inspector actions and palette alternatives. Each flow needs a fresh uninterrupted Tab/Shift-Tab/Enter/Space/Esc/arrows transcript, including failure recovery and the chosen target set—not just a button activation test.
2. **Visible focus — FAIL.** The definitive blocker is focus moving behind an open modal. Initial computed light-ring pairs include sub-3:1 values, but settled native-ring paint remains unverified rather than a proved additional violation. **Round 19 fix:** ADR-0006's Base UI Dialog must guarantee initial focus, containment/inert background, top-layer-only Escape, and return/fallback on cancel, success, nested-layer closure and deletion. Button/field/select/checkbox/tabs primitives must guarantee a visible, unclipped token ring in both themes, for every variant/tone/size, without a 200ms wait for discovery. Recheck native `auto` findings against painted output rather than depending on it.
3. **WCAG AA in both themes — FAIL.** Measured blockers: light tertiary **2.56:1**, light synced pill **3.67:1**, dark Explore Install **2.14:1**, dark Installed **1.82:1**, success toast **4.26:1**; unnamed controls and colour-only stale/failed states add semantic failures. **Round 19 fix:** test actual semantic-token foreground/background pairs, including raised surfaces, placeholder alpha, badges and Sonner; associate labels/descriptions and use display Tool names. Keep the decided hollow/filled/× strip and textual health distinctions. These findings do not certify untested WCAG criteria or all status variants.
4. **`prefers-reduced-motion` — FAIL.** Sonner has a reduction rule; the app's loops and `transition:all` do not. **Round 19 fix:** primitives own interruptible opacity/transform transitions and explicit reduced variants; progress retains names/counts and completion announcements without spin/shimmer. Frequent actions follow D6's near-invisible motion, not decorative choreography. Verify with the **real media preference true and false**, including an in-flight operation and focus movement.
5. **Minimum 960×640 with one structural collapse — FAIL.** Sampled normal-zoom surfaces mostly fit, but Projects truncates its identity and no structural collapse was observed. 200% fixture zoom scales the root, but full reflow/native-window coverage is incomplete. **Round 19 fix:** implement the agreed inspector-to-sheet boundary (around 1200px, exact threshold to settle), preserve action/focus order through the switch, and verify 960×640 plus 1280×800 in both themes. Guarantee dialog header/footer reachability, internal scroll focus visibility, and native minimum dimensions; include 200% text/zoom checks separately.
