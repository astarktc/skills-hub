## Standards

- **S1 — Blocking: operator-caused edit I/O failures bypass the typed-error contract.** `src-tauri/src/core/frontmatter_edit.rs:169–172` uses `read_to_string(path).with_context(|| format!("read {}", path.display()))?` and `std::fs::write(path, edited).with_context(|| format!("write {}", path.display()))?`; `skill_edits.rs:100` also propagates a raw read error. A readable but read-only `SKILL.md`, or non-UTF-8 upstream bytes, therefore produces `CommandError::Other`, not a structured condition. AGENTS.md, **Error wire contract**, requires “a condition the operator or upstream can cause is a typed variant”; ADR-0001 reserves `Other` for unclassified failures. Classify expected manifest read/write failures at the core seam and provide frontend EN/ZH copy. Missing-path handling alone does not cover them.

No additional documented-standard breaches or actionable Fowler smells identified. The catalog filter inside the guard is explicitly permitted by the ticket; the pure shared invocation maps avoid duplicated presentation logic.

## Spec

- **P1 — Blocking: a failed write can destroy the manifest.** `src-tauri/src/core/frontmatter_edit.rs:172` calls `std::fs::write(path, edited)` directly: it truncates the existing file before writing. An ENOSPC/short-write failure can leave an empty or partial `SKILL.md`, including for an imported skill whose central copy is its only truth. E10 requires “preserve the rest byte-for-byte”; E5 requires clearing to restore “upstream text exactly.” Neither is recoverable from the two-key base record after the body is truncated. Write a sibling temporary file completely before replacing the manifest; test an injected write failure. This is not the explicitly excluded rollback of finalize.

- **P2 — Blocking: failed database settlement loses the original base or leaves rows inconsistent with bytes.** `src-tauri/src/core/skill_edits.rs:103–128` writes/restores the file before independent edit-row operations, then calls `record_hash`; replay likewise ends with `store.upsert_skill_edit(&edit)?; record_hash(store, record)?` (175–176). If the first edit insert fails (for example SQLITE_FULL), bytes already contain the override but no base is persisted. Retrying captures those edited bytes as upstream, so Clear can never restore the original keys (E5: “clearing the edit restores upstream text exactly”). If replay updates the edit row but the skill upsert fails, the stored content hash still describes upstream while disk contains the override. The ticket says a replay failure leaves “the central copy already holds upstream bytes”; returning `Failed` alone does not establish that state. Make edit-row/hash settlement transactional and retain enough pre-edit bytes to undo the edit-stage failure—not the preceding finalize. Add fault-injection tests for insert/delete/hash/upsert failures.

Successful-path coverage is strong: the corpus exercises every mode, CRLF, duplicate keys, nested keys, malformed unclosed headers, and exact no-op/restore; integration tests cover replay, persistent conflicts, clear-to-current-upstream, Restore, Re-point, eligibility, propagation and migration/deletion. No scope-creep finding: the extra files are necessary wiring/shared presentation. Enabling unchanged Save for a conflicted override implements E6 resolution; extra base metadata is justified by E5.
