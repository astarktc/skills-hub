# 06: `imported` provenance — the central copy is the source of truth for a taken-over skill

Status: done — cbe48ad

**What to build:** A skill taken over from a Tool's skills directory is recorded with provenance `imported`: it has no source path; the Tool it was found in is kept as display-only history; its card says "Managed here", shows the found-in Tool, and offers no Update; Refresh (all) never puts it in the batch (it is not "skipped" — it is not a member) and single Update is not available for it. A Tool copy that `.skill-lock.json` identifies as installed by `npx skills add` still becomes a `git` skill with its real upstream. The glossary gains **Provenance** with the three kinds and their refresh/original-touching rules; an ADR records "an imported skill has no external source; the central copy is its truth" and why (the round-3 self-reference and the stale-row failures it produced).

Source: `../spec.md` Q1, Q2 and the "install_local_skill" / "single-skill update path" facts.

**Deviations**
1. **Schema version 9, not 8** (spec Q1 said "stays 8" assuming no new column). The found-in Tool got its own nullable column `imported_from_tool` as the orchestrator preferred — overloading `source_subpath` rejected. `ensure_schema` adds it for fresh DBs and for `user_version < 9`.
2. **Pre-existing bug fixed as a necessity**: the incremental-migration branch of `ensure_schema` never wrote `PRAGMA user_version` after migrating (only the fresh-DB branch did), so a <8 DB re-ran the V8 SQL on every launch — harmless for idempotent UPDATE/DELETE, fatal for `ALTER TABLE ADD COLUMN` ("duplicate column"). It now records `SCHEMA_VERSION` after the incremental steps; the v9 test calls `ensure_schema` twice to pin this.
3. Update availability on the card is driven by the DTO's `refreshable` (backend-owned rule), not by `sourceKind`; icon/label/source-line come from `sourceKind`. This is the ticket's own "so the UI doesn't re-derive the rule" resolved over its "derive Update availability from sourceKind" wording. Chose **hide** (not disable) for the Update button — there is nothing to explain in a disabled state that the tooltip on the source line doesn't already say.
4. `acquire_managed_skill_update_with`: the `if source_type == "git" / else if "local" / else bail` became `match Provenance::parse(..)` — rustfmt re-indented the git branch (~45 lines of whitespace-only diff in `installer.rs`). Behaviour identical except the else-arm, which is now the typed `NotRefreshable`.
5. `is_refreshable` answers **false for an unparseable `source_type`** too (there is no acquisition path for it); the backend only ever writes the three spellings, so this is a fence, not a behaviour change.
