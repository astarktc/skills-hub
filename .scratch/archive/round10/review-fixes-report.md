## Choices and ownership

**Manifest compatibility is based on the persisted Edit, not a second normal grammar.** `legacy_edit_header_end` requires `InvocationLines.had_frontmatter == true` and the former complete opening-fence spelling at the very start of the document. A read-only canonical projection delegates closing-fence recognition to the existing strict helper. It does not search later body blocks, accept delimiter prefixes, or broaden scalar/closing-fence rules.

- Clear's existing `restore_invocation_lines` uses this narrow fallback, restoring the recorded first/duplicate invocation lines in place. Existing atomic write and restore-before-delete order remain intact.
- Direct re-choose now calls `write_persisted_invocation_mode` with the existing base. This retains the legacy block and base, including same-mode no-op behavior, rather than inserting a second header or changing the base before a potentially failing byte write. A failed re-choose deliberately retains the newly chosen row value with the original restoration base, following the existing row-before-bytes rule.
- Normal metadata/invocation reads and fresh Edit capture/write remain strict. Thus normal reads of a legacy indented block still report no header/default invocation mode; compatibility does not legitimize that input globally.
- Replay/Update uses the **existing strict upstream capture and normal writer**, not the legacy writer. Fresh upstream bytes do not contain the old central Edit; restoring the old base into them would be incorrect. Replay captures their current base, so clear restores current upstream, including when that upstream is itself indented and therefore treated as body. Repeated Update never stacks synthetic headers. No replay/rollback production code changed.
- Existing serialized field spellings, DB schema, typed required I/O, permissions/atomic rename, content identity, Propagation, and catalog settlement are unchanged.

**Corpus expectations are independent literals.** `hadFrontmatter`, `rustMetadata` (name/description tuple or null), and `rustError` are distinct from TS `meta`/`body`. Added empty, comment-only, and missing-name headers. Rust can have a syntactic header without an accepted name; TS can display unnamed metadata or retain a metadata-empty document as body. No production UI or metadata policy change.
