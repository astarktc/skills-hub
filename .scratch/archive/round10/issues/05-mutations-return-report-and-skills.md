## Problem / verified evidence

- `src/hooks/useSkillLibrary.ts::refreshSkills` invokes `refreshManagedSkills` for both `null` (Refresh-all) and `[id]` (Update/Restore). `runSingleRefresh` also adapts both Re-point commands. Every returned refresh report currently reaches `refreshOutcome` whose default completion requests a reload; thrown single requests also reload before rethrowing.
- `commands/mod.rs::{refresh_managed_skills,repoint_local_skill_source,repoint_git_skill_source}` return bare `RefreshReportDto`. Update and Restore are not separate commands today. The core paths already converge: `refresh::refresh_managed_skills` / `refresh::repoint_git_skill[_with]` / `unlocatable::repoint_and_update` → `refresh_managed_skills_with` → guarded `skill_update::apply_unlocked` → finalize/Edit replay/Propagation, then auto-sync reassert in Refresh.
- `skill_edits::set_invocation_override` already returns `InvocationEditOutcome { entry, propagation }`. `commands/mod.rs::InvocationEditResultDto` maps it to `{ entry: ManagedSkillDto, propagation: Vec<PropagationTargetDto> }`. `useSkillLibrary::setInvocationOverride` reads **only entry**, replaces one row and closes the modal under an unconditional `successToast`. Backend propagation failures already remain report data; the missing work is the response/catalog contract and frontend interpretation, not adding backend fan-out.
- `skill_catalog::{managed_skill_catalog,managed_skill_entry}` already assemble presentation-ready entries (targets, invocation/override, refreshability, unlocatable/detachable). `get_managed_skills` maps the whole catalog through `ManagedSkillDto::from`. Reuse this assembly; a returned `skills` array is the full catalog, not a list of per-skill report rows.
- **Correction to Q13's historical future tense:** `refreshOutcome` already handles `status: "skipped_acquisition"` with `ACQUISITION_SKIP_KEY` (`skill_gone`, `stale_acquisition`). Bindings, EN/ZH reason keys and table-test fixtures already exist. Preserve and verify them across the new envelope rather than adding duplicate variants. `status.refreshSummarySkipped` still needs reason-neutral summary copy (backlog 21).
- **Preserve actual modal policy:** `refreshOutcome` closes after central refresh even with target/reassert failures or an Edit conflict; failed acquisition, skipped or empty result keeps it open. Table tests explicitly assert this. Warning severity and `completion.conflict` do not imply keep-open. `Outcome` already carries `{ reload, closeModal, conflict }` and notification actions carry IDs resolved against current state.
- `deleteManagedSkill` actually returns `()` / generated `null`, not a removal report; `deleteOutcome(null, ...)` reloads. Do not change that wire shape or ADR-0002 behavior here.

## Settled decisions / implementation

1. **Q7:** successful command responses for Update, Restore, both Re-points and Edit carry `{ report, skills }`, with the **complete post-operation Managed-skill catalog**. Apply it even when report data says failed/skipped/partial; those are valid responses whose catalog can reflect other completed changes or a vanished skill. Do not append/patch only the named skill. No success-path `getManagedSkills` invocation for these five actions.
2. Keep **Delete and Refresh-all refetching**, including their existing report/wire contracts. Keep import, Add, Detach, unsync and project-world behavior outside this migration. Avoid value-dependent untagged return types on `refreshManagedSkills`: a narrow single-skill command (e.g. `update_managed_skill`) used by both Update/Restore is an implementation option that preserves the batch command and still delegates to the existing batch-of-one core path. Do not copy the pool/settle implementation. State the concrete typed command design before editing and continue; this is an engineering choice, not a request to re-grill product scope.
3. Assemble `skills` through existing `managed_skill_catalog`, map through the existing DTO conversion, after the core operation has completed (including auto-sync reassert). Do not cache a pre-acquisition catalog or wrap acquisition/full-catalog scan in the Mutation guard. The promise is a fresh post-operation read, not an invented transactional snapshot across all filesystem/DB observations. A catalog read failure must propagate as a command error, never `skills: []` masquerading as success. Core keeps explicit roots/no `AppHandle`; commands remain wiring/DTO conversion. If a small result-composition seam is necessary for testing, keep it focused on this operation+catalog contract.
4. **Q18/Q6:** introduce/extend a pure Edit report fold in `src/lib/reportOutcome.ts` that consumes propagation, and retain the existing refresh fold policy for batch-of-one. The Edit report keeps meaningful Edit/propagation data; it need not be forcibly converted to a Refresh report. This is **not wave C report unification**. A global or project target failure yields structured notification entries, no unconditional saved success. Successful central Edit remains applied even when a target fails; use the established central-settled modal rule rather than letting a warning undo the save. Silent expected propagation skips remain silent; no extra auto-sync reassert for Edit.
5. Pure folds own all report interpretation and completion `{ reload, closeModal, conflict }`; migrated mutation folds request no reload because `skills` is already supplied. Hooks may unpack `response.report` and `response.skills`, apply the full array, call the fold and execute its completion. Hooks must not inspect nested report fields, counts, status, propagation or conflicts. Do not override a fold's `reload` in the hook based on report data. Preserve batch/single precedence conflict > failure > skipped > success, without dropping detail entries or introducing duplicate batch-of-one toasts. Keep notification actions ID-based; no `managedSkillsRef` resurrection.
6. Preserve failure recovery: existing Update/Restore/both Re-points thrown-request path reloads and does not close the repair modal. Edit currently leaves list/modal on a thrown error; do not silently broaden its recovery semantics. Returned Edit envelopes always replace skills, while thrown errors contain no valid snapshot. Preserve `runAction`/`toCommandError` ownership of errors.
7. **Q13:** retain acquisition skips and add end-to-end envelope proof that a `SkillGone` result removes the row via returned catalog, and `StaleAcquisition` retains the backend's current source/row. Make `status.refreshSummarySkipped` reason-neutral in **both EN and ZH**. The nested ternary follow-up (backlog 22) may be simplified only in the fold code already touched, preserving table-tested precedence; no unrelated notification cleanup.
8. Define serde/specta DTOs, keep typed `invokeTauri` callers and per-world type shims, regenerate `src/bindings/index.ts` via `cargo test`. Register any new command in `lib.rs::specta_builder`'s single `collect_commands!` list with both command annotations. Do not hand-mirror or edit bindings.
