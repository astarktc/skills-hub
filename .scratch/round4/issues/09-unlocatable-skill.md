# 09: Unlocatable skill — badge, Re-point / Detach / Restore / Remove, and Refresh skips it

Status: done — b3c2b6b

**What to build:** A Managed skill the app can no longer locate is marked on its card the moment the list loads, in one of two states: **source missing** (a `local` skill whose folder is gone) or **central missing** (the central copy is gone, so every Tool's link for it is dangling). Source missing offers **Re-point** (pick the folder's new location; the skill is then updated from it), **Detach** (it becomes `imported` — the central copy is truth from now on) and **Remove**. Central missing offers **Restore** (a `git` or `local` skill is re-acquired from its source and the central copy rebuilt) and **Remove**. Refresh (all) does not dispatch an unlocatable skill and never mints auto-sync targets for it; the batch summary is a warning that says how many were skipped and lists each. The state is computed from the stored paths at listing time and never stored. The glossary gains **Unlocatable skill**.

Source: `../spec.md` Q7 and the "reassert_auto_sync" fact; `../source-12-followups.md` #3.

**Deviations**
1. **Presence is `Path::exists()` (follows links), not `symlink_metadata`** as the spec's implementation note says. Reason: the acquire step judges the source with `exists()` and finalize/Propagation need a real central dir, so the listing and Update agree by construction — a dangling link *is* missing for every purpose here. Ticket 07's rule (iii) made the same call.
2. **Both paths gone → `source_missing`** (precedence decided here): Re-point's Update rebuilds the central copy, so that repair fixes both; Restore alone would fail on the missing source.
3. **`is_refreshable` semantics unchanged** (provenance only: "is there a source to re-acquire from?") — so a central-missing `git`/`local` skill still answers `refreshable: true` on the DTO, which is exactly what the card uses to decide whether Restore is offered (an imported skill with a missing central copy gets Remove only). Batch membership is the new `refresh_eligibility`; the three callers 06 named now split: `select_skills` → `refresh_eligibility`, `acquire_managed_skill_update_with` and `managed_skill_catalog` → `is_refreshable` (+ `unlocatable_state` for the listing).
4. **`CentralPathMissing` is no longer raised by Update at all** (not just "relaxed for Restore"): after the provenance check, every remaining case is a `git`/`local` skill, and re-acquiring one whose central copy is gone is Restore. The variant/code stays for `move_central_repo`. The commands test that pinned Update → `CENTRAL_PATH_MISSING` was rewritten to pin the wire shape via `from_anyhow` instead.
5. Re-point/Detach of a non-`local` skill is refused with a plain `anyhow` error (an `OTHER` on the wire), not a new typed code: the card offers them for `source_missing` only, so this is a caller guard, not an operator condition.
6. `SkillRecord` has no `PartialEq`; the unlocatable tests compare `format!("{:?}")` rather than adding a derive to `skill_store.rs`.
7. Not-in-gate: Prettier reports style issues in `useSkillLibrary.test.ts`/`useStatusReporter.ts` — they were not clean before this ticket either; ESLint (the gate) is clean. No reformatting done.
